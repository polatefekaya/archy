# Language-semantic adapter boundary

Archy's providers consume `LanguageSemanticAdapters` contracts, never a language-server client, Roslyn workspace object, or sidecar transport type. This keeps framework providers testable with deterministic fixtures and lets a language-specific implementation run either in the Native AOT host or behind a bounded sidecar.

The `language-semantic/v2` contract is source-generated for JSON and has an explicit request and response shape. A request identifies the repository root, immutable analysis snapshot, and the exact relative documents and content hashes that an adapter may analyze. An adapter response identifies its adapter ID, language, the same snapshot, its capabilities, and any available symbols, definitions, references, calls, inheritance facts, type facts, syntax sites, diagnostics, and source ranges.

Every document path and source range is repository-relative and one-based. A symbol's required `Range` is its stable declaration/selection range; its optional `ScopeRange` is the enclosing declaration span used to attribute references. The host validates the request and result before provider consumption. An adapter must report unavailable or degraded capabilities with diagnostics; it must not invent targets or silently return facts for a different snapshot.

The external LSP protocol, process lifecycle, JSON-RPC framing, and profile selection are separate implementation concerns. Standard LSP document-symbol, definition, and reference responses are normalized in `ExternalLanguageServerProtocol/NormalizeSemanticResponses`; a `LanguageServerProfileConfiguration` supplies the identity prefix and LSP `SymbolKind` mapping. The normalizer and the profile-driven identity policy contain no language-specific code.

`ConfiguredLspSemanticAnalyzer` executes every matching `language_server_profiles` entry with one Native-AOT-safe engine. Adding a standard-LSP language is a configuration change: declare its extensions, markers, command, arguments, language ID, identity prefix, and symbol mapping. The engine does not dynamically load executable code from configuration.

The analyzer reads a hash-verified profile-matching snapshot, starts the configured server, validates the typed initialize capability profile, opens the exact documents with the configured language ID, requests `textDocument/documentSymbol`, normalizes the JSON-RPC `result` through the configured identity policy, then independently collects references and outgoing calls only when their standard LSP capabilities are available and within the configured query bound. It closes documents and shuts down the session. A failed start, missing required document-symbol capability, synchronization failure, malformed declaration result, or conflicting identity returns an explicit degraded batch with no symbols; a relationship-only failure degrades only that relationship capability and emits no partial relationships. The workspace may still commit independent syntax/provider facts. A complete semantic batch is converted to graph nodes plus `contains`, `defines`, `references`, `calls`, and `inherits` edges and committed with the same immutable analysis run.

The generic engine currently emits declaration symbols, references, and outgoing-call hierarchy facts. It reports definitions, inheritance, type definitions, incoming calls, type facts, and syntax sites as unavailable even when a server advertises them. Those endpoints require independently tested, still-language-neutral query-site orchestration before Archy may claim their coverage.
